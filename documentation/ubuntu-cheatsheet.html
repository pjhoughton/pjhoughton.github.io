SSH Management


Description Command
Connect to a remote host ssh username@hostname
Connect using a specific key ssh -i ~/.ssh/id_ed25519 username@hostname
Connect on a non-standard port ssh -p 2222 username@hostname
Generate a new ED25519 SSH key pair ssh-keygen -t ed25519 -C "user@example.com"
Generate a new RSA SSH key pair ssh-keygen -t rsa -b 4096 -C "user@example.com"
Display public key cat ~/.ssh/id_ed25519.pub
Copy SSH key to a remote server ssh-copy-id username@hostname
Test SSH connectivity with verbose output ssh -v username@hostname
Very verbose SSH troubleshooting ssh -vvv username@hostname
List loaded SSH agent keys ssh-add -l
Add key to SSH agent ssh-add ~/.ssh/id_ed25519
Remove all keys from SSH agent ssh-add -D
View SSH client configuration cat ~/.ssh/config
Test SSH configuration for a host ssh -G hostname
Show remote host fingerprint ssh-keyscan hostname
Display fingerprint of a public key ssh-keygen -lf ~/.ssh/id_ed25519.pub
Remove a host from known_hosts ssh-keygen -R hostname
Remove a host/IP from known_hosts ssh-keygen -R 10.182.80.6
View known_hosts entries cat ~/.ssh/known_hosts
Create a local port forward ssh -L 8080:localhost:80 username@hostname
Create a remote port forward ssh -R 8080:localhost:80 username@hostname
Create a SOCKS proxy ssh -D 1080 username@hostname
Execute a command remotely ssh username@hostname "df -h"
Copy file to remote host (SCP) scp file.txt username@hostname:/tmp/
Copy file from remote host (SCP) scp username@hostname:/tmp/file.txt .
Synchronise folders over SSH (rsync) rsync -avz /source/ username@hostname:/destination/
Start SSH agent eval "$(ssh-agent -s)"
Test GitLab SSH authentication ssh -T git@gitlab.example.com
View SSH daemon configuration sudo cat /etc/ssh/sshd_config
Validate SSH daemon configuration sudo sshd -t
Restart SSH service sudo systemctl restart ssh
Check SSH service status sudo systemctl status ssh
Show active SSH sessions who

Permissions & Ownership

Description Command
Change permissions chmod 755 file
Change owner and group chown user:group file
View permissions ls -l

Common chmod Permissions

Permission values: 4 = Read (r), 2 = Write (w), 1 = Execute (x). Example: 755 = rwx r-x r-x

Permission Description Typical Use
chmod 777 file Everyone can read, write and execute Avoid in production. Temporary troubleshooting only.
chmod 755 script.sh Owner full access, others read and execute Scripts and executables.
chmod 775 directory Owner and group full access Shared application directories.
chmod 755 directory Standard directory permissions Most Linux directories.
chmod 644 file Owner read/write, others read Configuration files.
chmod 640 file Owner read/write, group read Application configs containing sensitive settings.
chmod 600 file Owner read/write only Passwords, secrets, certificates and private keys.
chmod 400 file Owner read only Highly protected secret files.
chmod 444 file Read only for everyone Files that should never be edited.
chmod 700 directory Owner full access only Private directories.
chmod 700 ~/.ssh Owner full access only SSH directory.
chmod 600 ~/.ssh/id_rsa Owner read/write only SSH private key.
chmod 644 ~/.ssh/id_rsa.pub Publicly readable SSH public key.
chmod 600 ~/.ssh/authorized_keys Owner read/write only SSH authorised keys file.
chmod 600 vault.yml Owner read/write only Ansible Vault encrypted files.
chmod 600 .vault_pass Owner read/write only Ansible Vault password files.
chmod 440 /etc/sudoers Read only for root and group Sudo configuration.
chmod 440 /etc/sudoers.d/* Read only for root and group Additional sudo rules.
